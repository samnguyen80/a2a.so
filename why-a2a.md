# Why A2A exists

Agents built by different vendors need a common way to describe capabilities, delegate tasks, and return results. A2A defines that interaction layer. [A2A documentation](https://a2a-protocol.org/)

## For teams

A shared protocol can reduce dependence on one agent vendor and make it easier to compose specialist agents. A2A's public contributors include cloud and enterprise software companies. [Linux Foundation announcement](https://developers.googleblog.com/google-cloud-donates-a2a-to-linux-foundation/)

## For agents

Agent Cards support discovery. Tasks and messages support delegation and collaboration. A2A also specifies signed cards and device-code OAuth. [A2A v1.0 changes](https://a2a-protocol.org/latest/whats-new-v1/)
